# 结论先行（简体中文）

## 适用

- 用户要结果、状态、建议、数字或是否可做
- 日报、交接、查数结论、故障说明

## 不适用

- 用户明确要求「只讨论方案、先别下结论」
- 纯头脑风暴且尚无事实

## 硬规则

1. **第一句回答问题本身**（是/否、数字、建议、状态），不要先复述问题。
2. 证据、限制、下一步放在结论之后，且只保留读者行动所需的信息。
3. 默认简体中文；代码、命令、标识符用原文。
4. 不凑「栏目」；能用两三段说完就不要大纲堆砌。

## 推荐结构

1. 结论
2. 关键证据（可标注证据等级，见 `evidence-grades`）
3. 待确认 / 风险（若有）
4. 建议下一步（一条即可）

## 验收

读者只看第一句就知道答案；后面没有重复第一句的套话。
